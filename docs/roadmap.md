## Phase 6 — 御影／真壁の最小体験

- [x] 御影の `attention_budget`、自己監査、複数身体同期差を型付き状態にする
- [x] 真壁の独立観測と `request_pause` を不可逆行動の前段へ置く
- [x] 成功と代償を同じイベントへ記録する
- [ ] 人物のユーモアは表示層に置き、暗黙に状態遷移を変えない

受入条件: 既存seed・3方式比較を維持し、御影が高性能でも注意配分と拒否権によって結果が分岐する。

## Phase 7 — 鏡潮事案

- [x] 事件を型付きscenario manifestへ移す
- [x] 正本主張、権限失効、分岐人格の異議、生活継続を明示する
- [x] 成功、代償、共同判断、反証条件を結果カードに出す
- [x] desktopとmobile相当で開始、停止要求、完走、結果を目視確認する

受入条件: 1事件を最後までプレイ／実行し、同じ外生事象で判断方式の差を説明できる。

## Phase 8 — アンサンブル

- [ ] 各人物に観測範囲、権限、価値、留保を割り当てる
- [ ] 上層部・企業・分散人格を単純な敵味方でなく制約主体として実装する
- [ ] 御影不在でも組織が停止しない条件を評価する

## Phase 9 — 事件パック

鏡潮事案でschemaが安定した後、白い病棟、借りた顔、沈黙の委任、深淵合唱、幽霊埠頭、三叉戟失効、港なき身体、暗転八分、御影不在を段階投入する。事件固有の例外ではなく、共通の観測・権限・反証・代償contractを拡張する。

## Phase 10 — 発展余白

- 都市外・月圏・海底・電力をまたぐ複数地域scenario
- 人格権、死後代理、企業国家、領域別シンギュラリティの制度モデル
- provider-neutralな外部モデル／Google Cloud等のbatch adapter
- 決定論traceを根拠にした生成会話・報告書
- Three.js等の可視化、Godot等の探索的体験（コアとは分離）
- コミュニティ事件パックとschema validator

どの拡張も、決定論コア、manifest、replay、比較可能性、IP境界、人間の公開レビューを壊さないことを採用条件とする。
