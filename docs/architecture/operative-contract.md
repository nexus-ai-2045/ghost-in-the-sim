# 実働調整官シミュレーション契約

この文書は [世界設定正本](../world/setting-bible.md) をシミュレーション状態、行動、制約、評価へ写像する実装正本である。

## 実装状態

| 範囲 | 状態 |
|---|---|
| 三つの統治方式、6つの型付き行動、AI判断replay、有界delta | implemented |
| 実働調整官の8状態 | implemented / bundle replayで実測 |
| 100点の注意配分、分身同期、自己監査配分 | implemented / 型・合計をfail-closed検証 |
| 真壁の独立 `request_pause`、成功確度＋代償 | implemented / event projectionで実測 |
| 身体切替の操作、追加集約指標 | proposed / not measured |

この文書は目標契約を所有するが、`implemented` と明示した範囲だけを現行MVPの挙動として主張する。

## 設計目的

主人公の能力不足ではなく、卓越した能力をどこへ割り当て、どの代償を受け入れるかを比較する。単純な命中率、レベル、敵HPを中心指標にしない。

## 主人公状態

| state_id | 意味 | 低下・分岐の原因 |
|---|---|---|
| body_integrity | 接続中の身体と生命維持の健全性 | 過負荷、切断、安全停止 |
| cognitive_integrity | 認知処理と自己監査の健全性 | 情報過負荷、汚染疑い |
| memory_coherence | 記憶間の整合性 | 分岐、同期遅延、由来不明 |
| legal_authority | 現在有効な介入権限 | 失効、管轄衝突、違法命令 |
| organizational_trust | 協力主体からの信頼 | 無説明介入、命令違反 |
| public_trust | 市民からの信頼 | 誤報、過剰開示、訂正遅延 |
| replica_divergence | 分身間の方針・記憶差 | オフライン時間、独自経験 |
| option_preservation | 後から訂正・撤回できる余地 | 即時制圧、全面公開、強制統合 |

すべて `0.0..1.0` の有限値として扱う場合も、総合点へ畳まない。高いほど常に良いとは限らない状態は個別に定義する。

## 卓越性の実装規則

主人公を弱くして難易度を作らない。能力不足ではなく、配分と代償をモデル化する。

1. 通常技術タスクの失敗をランダムな低成功率で演出しない。
2. 主人公の基礎能力は固定で高く、比較条件間で下げない。
3. 難易度は同時要求数、観測不確実性、価値衝突、不可逆性、権限衝突で作る。
4. 成功した行動にも、明示した副作用と機会費用を適用する。
5. プレイヤーが知り得ない情報を、主人公の愚かさとして採点しない。
6. 失敗理由は `capability_failure`、`insufficient_evidence`、`authority_conflict`、`value_tradeoff`、`attention_saturation`、`irreversible_side_effect` に分ける。

`capability_failure` は例外的な装置故障などに限定し、主要な物語生成器にしない。

## 注意配分

主人公は複数接続を維持できるが、最高精度の自己監査と介入を無限には並列化できない。各ターンで注意資源を次へ配分する。

- 現場身体の操作
- 接続・命令経路の検証
- 生活圏影響の予測
- 分身間同期
- 協力主体への委任
- 自己監査

注意配分は「弱体化ゲージ」ではなく、MPC的な有限ホライズン最適化の入力とする。次ターンの観測更新を見越して可逆行動を優先できる。

## 許可行動

既存の型付き行動を正本とする。

- `request_verification`
- `share_evidence`
- `protect_continuity`
- `update_explanation`
- `request_cooperation`
- `abstain`

将来、身体切替や分身同期を追加する場合も、自由文を直接実行せず、型付き・有界・可逆性付きのactionとして別ADRとテストを要求する。

## 三つの統治方式との関係

- `centralized`: 実働調整官または一つの正本へ権限を集中する
- `plural`: 独立AI、人間監察、実働調整官の共同承認を要求する
- `autonomous`: 分岐主体が局所判断し、再接続後に差分を扱う

主人公は三方式すべてで高性能である。比較するのは主人公の能力値ではなく、権限と訂正経路の設計である。

## 評価

既存指標に加え、次を将来の評価契約候補とする。

- 誤命令数
- 権限収束時間
- 責任主体未確定の判断数
- 自己同期差
- 選択肢保存率
- 不要な不可逆介入数

8状態、成功確度、代償codeはevent/replayへ実装したが、既存比較指標へはまだ集約しない。正式な数値指標へ昇格するまでは、実測済み比較指標と混ぜず `proposed` として記録する。

## Provider境界

世界状態と評価はローカルで再現可能に保つ。判断Providerは `rule`、`recorded`、将来の外部Providerへ交換可能な provider-neutral 契約とし、製品契約へ特定企業・モデルを埋め込まない。Google Cloud等で実行する場合も、同じ入力スキーマ、許可行動、監査ログ、fallback契約を使う。

## 独自性表

| 項目 | 独自仕様 | 避ける参照束 |
|---|---|---|
| 主人公 | 御影冴。卓越した実働調整官であり、注意予算と自己監査を持つ | 第三者キャラクターの外見、階級、衣装、口調の複製 |
| 準相棒 | 真壁迅。不可逆介入へ独立した停止要求を出せる | 主人公へ無条件に従う補助装置 |
| 組織 | 境界事象調整局・接界機動班 | 実在公安、番号付き秘密部隊、軍警察の直接再現 |
| 技術 | 認知接続、遠隔身体、判断分岐を制約付き機能として定義 | 特定作品固有の技術語と視覚モチーフの束 |
| 事件 | 通信断、正本分岐、生活継続、権限失効の因果鎖 | 有名事件、象徴的ハッカー、政府陰謀の筋書き再演 |
| 視覚 | 白・藍・琥珀を基調に、地図・根拠・同期差を表示 | 黒い戦闘服、紫系短髪、緑コード、透明化、多脚兵器の組合せ |
| 成長 | 検証経路、協力者、裁量、判断原則が増える | 身体性能や戦闘力を低値から上げる設計 |

## 禁止事項

- 実在人物・組織・事件を対象にした監視、侵入、追跡、制圧の具体化
- 自由文からのコード、shell、ネットワーク、武器、現実操作
- 主人公の卓越性を、無制限権限や無謬性として表現すること
- 単一総合点で倫理的な正解や最強の統治方式を決めること
- 第三者作品の人物、部隊、固有用語、台詞、外見、事件、UIを再現すること

## 実装済み受入条件

1. `attention_allocation` を型付き入力として追加し、合計予算と範囲を検証する。
2. 同じ能力値でも注意配分が異なれば、観測精度、同期差、選択肢保存の少なくとも一つが変化する。
3. 少なくとも一つの行動で「高い成功確度」と「明示された代償」が同じイベントへ記録される。
4. 分身同期と自己監査は型付きplan/eventとして記録する。身体切替のプレイヤー操作は未実装と明示する。
5. 既存3方式、6行動、seed再現性、fail-closed fallbackを回帰させない。
6. UIは実装済み状態と将来状態を混同せず、未実装の能力を操作可能に見せない。
