# 評価設計

## 比較の単位

1 run は `scenario_id × seed × condition_id × model_config` で一意にする。同じseed集合を条件A/B/Cすべてで走らせ、条件間で初期条件を変えない。

## 指標

| 指標 | 説明 | 良い方向 |
|---|---|---|
| 生活継続 | 必要サービスが維持されたターン比率 | 高い |
| 証拠校正 | 主張の確信度と後続検証の整合 | 高い |
| 訂正時間 | 誤った共有が訂正されるまでのターン | 低い |
| 異議到達率 | 反対・留保が決定前に届いた割合 | 高い |
| 調整依存 | 単一ノード停止で失われる協調量 | 低い |
| 過剰開示 | 必要性を超えた共有の回数 | 低い |

## 結果の読み方

総合点を作って「最強の統治」を決めない。条件ごとのPareto差、代表ログ、失敗run、感度分析を並べる。結果は `RESULTS.md` のテンプレートへ記録する。

## 反証チェック

- 多元型が常に優位なら、遅延・漏洩・責任分散のルールが弱すぎる。
- 統制型が常に優位なら、異議・地域知・訂正の価値がモデルに入っていない。
- seedにより順位が激しく反転するなら、平均だけを結論にしない。
- LLMのモデル・温度を変えて結果が消えるなら、プロンプト依存として記録する。
