# 提出デモ進行台本

この文書は、現在の追跡済みUIと再現可能なruntimeだけを説明する発表用の正本です。未実装のlive provider、現実予測、政策推奨を実装済みとして語りません。

## 3分デモ

### 0:00–0:25 — 問い

2036年の海洋複合都市圏ポセイドンで、病院と港湾へ配備された危機対応AIの記憶と権限が通信障害で分岐します。プレイヤーは御影冴として、生活を止めずに「どの命令を正本とするか」「誰の異議を残すか」を判断します。

### 0:25–0:50 — 条件を選ぶ

1. `病院を守る` または `港湾を守る` を選ぶ。
2. `真壁と共同確認する` または `御影が単一正本で進める` を選ぶ。
3. `作戦開始`を押す。

ここで変えるのは統治方式と注意配分です。事件の外生事象とseedは固定されるため、結果差を条件差として比較できます。

### 0:50–1:40 — AI創発を観測する

ターンを進め、御影、真壁、病院複製AI、港湾複製AIの提案・協力・異議を確認します。画面は追跡済みrun bundleを表示し、ブラウザ内で結果を作り直しません。

第8ターンでは真壁が不可逆操作の停止を要求します。`保留する`と`進行する`は成功率だけでなく、生活継続、訂正可能性、異議保存、責任配分という別の代償を残します。

### 1:40–2:20 — 結果と反証可能性

12ターン完了後、結果カードで次を示します。

- 成功と代償
- 共同判断と保存された異議
- 生活継続、誤命令、訂正時間、権限収束、不可逆損失
- 同じseedに対する中央正本型、複数承認型、自律分身型の比較
- `run_id`、event順序、replay証拠

「AIが賢かったから成功した」ではなく、観測範囲、権限、反証、有限注意がどの状態遷移へ効いたかを説明します。

### 2:20–3:00 — 外部AIへの引継ぎ

ローカルrule providerは再現可能なbaselineです。外部AIを使う場合も未来12ターンを一括生成せず、`session-init`と`session-advance`で一手ずつ確定します。各応答はdigest、主体、turn、欠落、重複を検証し、最終的に同じ`meta-security-run-bundle/v1`へ閉じます。credential、network、provider SDKはこのリポジトリのruntime正本へ混ぜません。

## 実行前チェック

```powershell
$env:PYTHONPATH = "src"
py -3.13 -m ghost_in_the_sim.batch_cli --output web/data/comparison.json --actual-ai-evidence-trace fixtures/actual-ai-trace-seed42.json
py -3.13 scripts/serve_demo.py
```

ブラウザで `http://127.0.0.1:8045/` を開き、病院／港湾の両経路、共同確認、第8ターンの保留、12ターン完了、結果カードを確認します。

## 発表で断定しないこと

- 現実の危機対応結果を予測するものではない。
- 特定の政策や統治方式を倫理的正解として推薦しない。
- 生成AIの自由文にruntimeルールを書き換えさせない。
- 外部AIの提案を検証なしで採用しない。
- CI成功を公開承認や第三者素材の権利確認の代わりにしない。
