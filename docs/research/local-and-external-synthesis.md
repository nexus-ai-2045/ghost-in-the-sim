# ローカル知識と外部先行事例の統合メモ

## 目的と境界

この文書は、`Ghost in the Sim` を「もっともらしい未来予測」ではなく、条件を固定して
比較・反証できる社会シミュレーションとして育てるための入力台帳である。

- 現実の危機、国家、組織、個人の能力・意図・行動を推定しない。
- 創作IPの作品名、人物、画像、台詞、設定、作風を使わない。抽象化された設計上の問いだけを扱う。
- 第三者コードをコピーしない。採用は契約・測定方法・検証習慣に限り、実装時にライセンスを再確認する。
- ローカルの別SSOTは複製しない。ここには利用した抽象と追跡先だけを記す。

## 採用する設計原則

| 原則 | 根拠 | このrepoへの反映 | 反証・停止線 |
|---|---|---|---|
| 決定論的な世界と解釈層を分ける | 現行ADR-004、内部SSOTのワールドエンジン分離 | 状態遷移、seed、比較条件は純粋関数で保持し、LLMは後付けadapterにする | LLMなしで同じrunを再生できなければLLM接続を追加しない |
| 比較は同一初期条件・複数seedで行う | 現行評価契約、NetLogo BehaviorSpace、Mesa batch run | `scenario_id × condition_id × seed × model_config` をrun IDにする | 条件ごとにseedや情報予算が違えば比較結果を無効扱いにする |
| 単一スコアに畳まない | 現行評価契約、内部SSOTのPareto比較 | 継続性、訂正、異議、開示、依存、回復を並列に保存する | 勝者だけを出力するUI・報告は禁止する |
| モデル記述と実装を相互照合する | ODD protocol、現行`model.odd.md` | scenario card、状態変数、schedule、指標、反証条件を同じPRで更新する | 文書とfixtureの差分は設計契約テストで検知する |
| 統治・利用目的・測定を分ける | NIST AI RMFの Govern / Map / Measure / Manage | 目的外利用、異議、訂正、データ離脱を成果指標と副作用の両方に置く | 利益だけを測り、被害・離脱・格差を測れない条件は実験候補にしない |
| 外部フレームワークは参照し、早期依存しない | Mesa、NetLogo、既存の軽量Python実装 | 初期MVPは標準ライブラリ中心の決定論コアを維持する | UI、空間、batch実行が必要になった時だけMesa/NetLogoを選定レビューする |

## ローカル知識からのシナリオ候補

以下は実在の政策や事件のモデルではなく、比較実験に変換できる**抽象シナリオカード候補**である。
採用は人間レビュー後に1件ずつ行う。

| card_id | 因果連鎖 | 比較したい制度条件 | 主な測定 | 重要な反証 |
|---|---|---|---|---|
| S-001 ポセイドン | 公共データ連携障害 → 物流遅延 → 不確かな情報拡散 → 調整 | 統制型 / 多元型 / 接続過多 | 生活継続、訂正時間、異議到達、開示、依存 | 多元型が情報量や善意を追加しないと成立しない |
| S-002 相互運用インターロック | 時刻・通信の異常 → 自動措置の誤作動 → 連鎖停止 → 誤認 | 調整なし / 掲示板のみ / 翻訳・独立検証・分散保留 / 中央集権 | 不要停止、訂正時間、二次被害、参加継続、権限集中 | 調整機構が単一障害点になる、または合意待ちで必要措置を遅らせる |
| S-003 避難スコアの街 | 災害リスク上昇 → 個人評価 → 救命改善 → 二次利用・不信 → データ離脱 | 一律案内 / 非公開評価 / 用途選択・異議申立て | 見逃し、誤介入、格差、信頼、離脱、訂正率、回復時間 | 参加型制度が救命や公平性を改善せず、手続だけを増やす |

`S-002` と `S-003` は、現行MVPへ自動で入れない。まずS-001でrun manifest・比較・ログ・反証表示を完成させる。

## 物語・IPを扱うときの入口

創作は「未来社会の制度矛盾を想像する入口」にはなり得るが、初期MVPのモデル入力にはしない。

1. 作品固有の要素を使わず、問いを一般語へ翻訳する。
2. 問いを因果連鎖、主体、制約、比較条件、観測指標、反証条件へ分解する。
3. オリジナルfixtureで実装し、物語由来かどうかに依存しない実験にする。
4. 権利者・公式協力・作品風表現を示すUIやREADME表現は使わない。

## 実装へ落とす最小契約

次の4ファイルを、Phase 1の完了条件に追加する候補とする。

| 成果物 | 必須フィールド | 目的 |
|---|---|---|
| `scenario` | `scenario_id`, 状態変数, 外生イベント, 非対象 | 世界設定の境界を固定する |
| `experiment` | `condition_id`, seed集合, 情報予算, ターン数, 指標 | 公平な条件比較を固定する |
| `run_manifest` | コード版, scenario, experiment, seed, 実行時刻, 出力ハッシュ | replayと追跡を可能にする |
| `result_card` | Pareto指標, 代表ログ, 失敗run, 反証判定, 限界 | 結果を結論ではなく検証可能な観測として示す |

## 外部先行事例から採用しないもの

- MesaやNetLogoのフレームワークを、現段階で依存関係として導入しない。
- NIST AI RMFを「適合」や外部認証の根拠として使わない。ここではリスク項目の漏れを減らす参照枠に限る。
- 研究・GitHub実装のシナリオ、データ、人物像、コードをコピーしない。
- 実在の地政学・安全保障の予測器、運用手順、帰属判断器へ拡張しない。

## 次の人間判断

1. 初期MVPはS-001だけで完走させるか。
2. S-002、S-003をPhase 2以降の候補として保持するか。
3. `scenario / experiment / run_manifest / result_card` の4契約をPhase 1の受入条件として採用するか。
4. 決定論コアが十分になった後、MesaをUI・batch実行の候補として評価するか。
